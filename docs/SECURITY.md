# Безопасность

- Пароли хешируются с помощью scrypt. Сеанс использует случайный токен, в базе хранится его SHA-256. Выход отзывает конкретный токен. Cookies используют HttpOnly, SameSite=Lax и Secure в промышленном режиме. Срок сеанса — восемь часов. PostgreSQL хранит общие для всех процессов квоты по адресу клиента и идентификатору учётной записи. За 15-минутное окно принимаются до 30 попыток с адреса и до 8 на учётную запись. При превышении возвращается HTTP 429 с Retry-After. Изменение данных сотрудника отзывает его текущие сеансы.
- Все HTML-формы защищает Flask-WTF CSRF. Приложение задаёт CSP, запрет встраивания и `nosniff`. Ошибки авторизации не раскрывают существование чужих счетов и вложений.
- Инициатор видит свои счета. Доступ могут иметь назначенные участники маршрута и фактические исполнители прошлых этапов. Полный обзор имеют администратор, финансовый контролёр, директор, бухгалтер и наблюдатель. Право выполнять этап определяется назначением. Инициатор может выполнить этап своего счёта только при явном разрешении в снимке маршрута. Бухгалтер регистрирует платежи, а роль наблюдателя предназначена для чтения.
- Версия счёта проверяется при сохранении. Внешние ключи, ограничения сумм и уникальность идентификатора запроса и номера поручения в счёте защищают согласованность платежей.
- Для файлов проверяются размер, сигнатура и структура. Изображения декодируются с ограничением по числу пикселей. Для XLSX ограничены объём распакованных данных, внешние связи и вложенные бинарные объекты. Для PDF отклоняются зашифрованные документы, активные действия и вложения известных типов. Документы выдаются после проверки прав через endpoint скачивания с `Content-Disposition: attachment`.
- В промышленной среде файлы находятся в закрытом bucket Supabase. Приложение проверяет приватность bucket при каждой загрузке и скачивании, а серверный ключ `sb_secret_` хранится в окружении Render. Flask передаёт его в `apikey` только по HTTPS к настроенному проекту Supabase. Запросы Storage не следуют перенаправлениям. В локальной среде используются случайные имена под `instance/documents`, вне статического каталога.
- События счета и связанный аудит фиксируются одной транзакцией. Доступ к общему журналу имеет администратор. В журнале приложения нет функций редактирования и удаления событий.

Перед подключением реальных документов настройте антивирусную проверку по политике компании. Структурная проверка файлов не заменяет антивирус. Для журналов и документов согласуйте сроки хранения и резервное копирование. При сбое связи после записи объекта сверьте записи вложений с закрытым bucket. Операция записи в PostgreSQL и операция Supabase Storage выполняются разными сервисами.

Промышленное соединение PostgreSQL требует TLS. Приложение использует закрытую схему `vaim`, которой нет среди схем Data API Supabase. Для задания прав базы и Storage используйте инструкцию по развёртыванию.
